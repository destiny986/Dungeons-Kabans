# Рабочая папка проекта

По указанию пользователя постоянная рабочая папка проекта — `C:\dev\Dungeons-Kabans`.

- Все последующие изменения кода, документации и результаты работы сохранять в `C:\dev\Dungeons-Kabans`.
- Если чат или инструмент открыт в другой копии, в том числе в `.codex/worktrees`, перед работой перейти в `C:\dev\Dungeons-Kabans` и явно указывать её как рабочую директорию команд.
- Не оставлять итоговые изменения только во временной копии или отдельном worktree. Новые worktree создавать только по явному запросу пользователя; ветки Git можно использовать в основной папке.
- Локальные данные, изображения и служебные результаты также хранить внутри основной папки, соблюдая `.gitignore`. Секреты и рабочие базы не добавлять в Git.

## Назначение и стек

Русскоязычный игровой дневник для одного мастера и небольшой группы игроков:
персонажи, каталог предметов, действий и событий, ресурсы и приватный чат.
Приложение списывает ресурсы и записывает действия, но не рассчитывает урон,
эффекты и правила D&D. Сохранять русский язык интерфейса и сообщений об ошибках.

Стек: Python 3.12, Django 5.2 LTS, SQLite, Django templates, HTMX и GridStack.
Зависимости закреплены в `requirements.txt`. Клиентские библиотеки находятся в
`game/static/game/vendor/`; приложение работает без CDN и сборки JavaScript.

## Карта проекта

- `config/` — настройки окружения, корневые URL, WSGI/ASGI.
- `game/models.py`, `constants.py`, `migrations/` — модель данных и миграции.
- `game/access.py`, `access_views.py`, `access_urls.py` — доступ мастера,
  приглашения и браузерные доступы к персонажам.
- `game/operations.py`, `chat.py` — атомарные игровые операции и приватный чат.
- `game/catalog.py`, `forms.py`, `validators.py`, `media.py`, `signals.py` —
  каталог, редактирование, проверка и жизненный цикл изображений.
- `game/archives/` — проверка, сравнение, импорт и экспорт ZIP.
- `game/web/`, `game/urls.py` — HTTP-интеграция сервисов.
- `game/templates/game/`, `game/static/game/` — интерфейс, CSS и JavaScript.
- `game/management/commands/` — локальный запуск, настройка мастера и очистка импортов.
- `game/test_*.py`, `tests/` — Python-тесты и JavaScript-проверка массового выбора.
- `deploy/`, `Dockerfile`, `compose.production.yaml`, `.github/workflows/ci.yml` — доставка и CI.

## Окружение и запуск

Выполнять команды PowerShell из корня проекта. Использовать `.venv` явно;
активация окружения не требуется. Для первоначальной установки:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Локальный запуск:

```powershell
.\.venv\Scripts\python.exe manage.py serve_game
```

`serve_game` применяет миграции, настраивает мастера, собирает статику и запускает
сервер на `127.0.0.1:8000`. При первом запуске нужен пароль из `MASTER_PASSWORD`
либо интерактивный ввод. Команда предназначена только для `DJANGO_ENV=local`.
Django сам не загружает `.env`: переменные задаёт окружение процесса;
`.env.example` служит справочником. Не выводить секреты при диагностике.

## Проверки изменений

Основные команды совпадают с проверками README и CI:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
node --check game/static/game/app.js
node tests/import_bulk.test.cjs
```

Для быстрой проверки области можно указать модуль, например
`.\.venv\Scripts\python.exe -m pytest game/test_access.py -q`.
После изменений моделей создавать и включать соответствующие миграции.
Тестировать на отдельной тестовой базе и временных каталогах; проверка
конкурентности использует файловую SQLite. Не использовать рабочую базу для тестовых данных.
Node.js нужен для JavaScript-проверок, но не для запуска приложения.
При изменениях доставки учитывать дополнительные проверки CI: production
`check --deploy --fail-level WARNING`, `bash -n` для shell-скриптов и Docker smoke.
Shell-скрипты сохранять с LF согласно `.gitattributes`.
Для изменений только документации достаточно проверить ссылки и `git diff --check`.

## Правила изменения поведения

- Перед изменением области читать соответствующий контракт из `docs/`.
  Сохранять существующее разделение HTTP-обработчиков и сервисной логики.
- Проверять права через `game.access`: `request.user` не является источником
  игровых прав. Доступ мастера не даёт доступ игрока; один браузер может иметь
  несколько независимых ролей. Сохранять приватность чата и защищённую выдачу медиа.
- Изменяющие HTTP-запросы требуют POST и CSRF, кроме явно описанного в контракте
  погашения приглашения через GET. Проверять права внутри атомарных операций.
- Сохранять короткие транзакции SQLite, WAL/IMMEDIATE, идемпотентность по
  `request_id`, проверки `revision` и явное подтверждение более высокой ячейки.
- Пользоваться существующими сервисами PNG и ZIP: сохранять проверки путей,
  ограничения файлов, дедупликацию и удаление неиспользуемых файлов после commit БД.
- При изменении HTMX сохранять OOB-обновления, черновики, фокус, выбранные вкладки
  и открытые подтверждения. Не сбрасывать UUID операции при ошибке запроса.
  Изменения интерфейса проверять также в браузере на мобильной и настольной ширине.
- Расширять существующие тесты по затронутому поведению; при изменении контракта
  обновлять соответствующую документацию. Не редактировать сторонние vendor-файлы
  как обычный код приложения.

## Локальные данные и доставка

`data/db.sqlite3` — рабочая база, `data/media/` — изображения,
`data/imports/` — временные импорты. Пути переопределяются через `DATA_DIR`,
`MEDIA_ROOT`, `IMPORT_ROOT`. Каталоги создаются автоматически; они исключены из
Git и не нужны в commit/push. Не добавлять принудительно данные, `.env`, секреты,
виртуальные окружения, `staticfiles/` и служебные артефакты. Перенос данных
выполняется отдельно от Git; игровой ZIP не включает чат, пароли и сессии.

Push в `release` запускает доставку после CI. Без прямого запроса пользователя
не отправлять эту ветку и не изменять производственный сервер. Данные хранятся
вне образа; автоматических резервных копий и отката нет. Учитывать совместимость
миграций при изменениях доставки.
