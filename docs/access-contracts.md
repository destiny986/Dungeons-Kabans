# Browser access contracts

Import helpers from `game.access`. `has_master_access(request)` compares the fixed active `master` user's current auth hash with `master_auth_hash` in the DB-backed browser session. Password changes remove only the master capability. Django `login()` is not used; `request.user` is not an authorization source here.

`get_character_grant(request, character_id)` returns a grant or `None`. It requires an existing browser session, active character, unrevoked grant and invitation, matching character IDs, and grant/invitation/current-character generations. Master access never implies player access. `roles_for_request(request)` returns `{label,url}` dictionaries for master and every valid character grant.

Use `@master_required` for master endpoints. Use `@character_required` for endpoints with URL `pk`, or `@character_required(parameter='character_id')` for a differently named character argument. The latter attaches `request.character_grant`, including its selected `character`. Both decorators preserve wrapped signatures and support positional character IDs. Ordinary denials redirect to `game:index`; HTMX denials return HTTP 200 with `HX-Redirect` pointing there and an empty body. `access_denied(request)` is available for manual authorization branches. HTTP-method decorators and CSRF protection remain the caller's responsibility.

`issue_invitation(character)` returns `(token, CharacterInvitation)`. Tokens deterministically sign UUID/generation with the Django secret and a dedicated salt; only SHA256 digests are stored. Redisplay returns the same reusable link for that generation. `redeem_invitation(request, token)` returns the browser grant and activates the character, or raises `InvalidInvitation` with no token in its message. Repeated redemption retains the grant ID. `revoke_character(character)` atomically revokes all invitations and browser grants, increments generation and deactivates that character. These services lock/reload the character; refresh a previously held instance before examining changed state.

Include/concatenate `game.access_urls.urlpatterns` inside the `game` namespace alongside real application routes. Names provided: `index`, `master_login`, `join(token)`, `invite(pk)`, `revoke(pk)`, `media(digest)`. Access redirects also require `game:master` and `game:player(pk)`, supplied by application integration. No product placeholder routes are provided.

Master login accepts POST `password`, authenticates and rotates the session key, migrating all CharacterGrant session keys. Existing session data survives. Invalid credentials render `index.html` with field errors and HTTP 400. Sessions retain the foundation's 30-day lifetime. Invite and revoke are master-only POST endpoints protected by CSRF; invite POST follows the coordinator's integration ruling because first display creates metadata. Join GET deliberately redeems immediately then redirects to player. Invite/join responses use no-store and no-referrer headers. Invitation UI context follows `docs/ui-contracts.md`; QR PNG generation is local. `PUBLIC_BASE_URL` is preferred, preserving its configured port; an empty setting uses Django's validated request host.

Media GET returns 404 for denied or unavailable assets. Master can read any asset; valid browser grants can read their portraits, inventory/action icons, and item/action icons referenced by their received or sent chat. Paths must be flat `<digest>.png`, resolve to a regular file within MEDIA_ROOT, and never escape it through symlinks. DEBUG returns FileResponse; production returns `X-Accel-Redirect: /_protected_media/<digest>.png`. Both use image/png and private/no-store. Reverse-proxy internal media configuration remains required.

`manage.py bootstrap_master` reads `settings.MASTER_PASSWORD` (populated from environment), rejects empty values and accepts no password argument. Repeated identical passwords retain the exact encoded hash, even when the preferred hasher changes. A changed password replaces the hash and invalidates master access on its next permission check.

Deployment must suppress/redact `/join/` paths in reverse-proxy and application access logs; response headers cannot control infrastructure logging. No logging/settings files are owned by this module. Rotating SECRET_KEY invalidates signatures and master auth hashes. The Windows test environment cannot create symlinks without additional privilege, so that one filesystem test skips locally; path traversal and missing files are tested.
