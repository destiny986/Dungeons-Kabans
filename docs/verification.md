# Проверка реализации Dungeons & Kabans

Реализация выполнена в отдельной ветке `codex/dnd-companion`. Исходное ТЗ и согласованные уточнения находятся в `docs/superpowers`. Боевой сервер не изменялся; деплой, запуск workflow и отправка в `release` не выполнялись.

## Что подготовлено

| Область | Результат |
| --- | --- |
| Данные | Модели, ограничения и начальная миграция; каталог, листы персонажей, девять ресурсов, инвентарь и назначения. |
| Доступ | Независимые роли в одной серверной сессии; пароль мастера, QR, многоразовое приглашение и отзыв. |
| Каталог и формы | Нормализованные имена, кириллический поиск, PNG, все поля листа, сохранение скрытых ресурсов и защита устаревших форм. |
| Игра и чат | Атомарные выдачи, списания, здоровье, отдых, приватные сообщения, идемпотентность и подтверждение более высокой ячейки. |
| Интерфейс | Пять секций мастера, пять вкладок игрока, локальные HTMX/GridStack, карточки, предпросмотр, адаптивная вёрстка. |
| Перенос | ZIP v1, проверка ссылок/изображений, сравнение конфликтов, сохранение идентичности, отмена и очистка временных файлов. |
| Доставка | Docker, отдельный Compose/nginx, CI и release workflow, часовая очистка оставшихся импортов. |

## Проверки

Заключительная проверка 30 октября 2026 года: **158 passed, 2 skipped, 30 subtests passed**, 29,83 секунды. Единственное предупреждение создаёт намеренно повреждённый ZIP с повторным именем для проверки отказа. Отдельно проходят реальная JavaScript-проверка массового выбора и проверка синтаксиса app.js; эти команды включены в CI. Обычный Django check, проверка отсутствия новых миграций и production check проходят. Один HSTS check намеренно отключён для согласованного общего IP. Production collectstatic проходит: 135 файлов, 375 post-processed. Проверка pip не обнаружила несовместимых зависимостей. Независимое общее ревью и одно ревью заключительного набора исправлений: spec PASS, quality PASS, незакрытых замечаний нет.

В настоящем браузере проверены:

- Ширины 360, 768 и 1440 px без горизонтального переполнения страницы; на мобильной ширине пять секций мастера стоят вертикально.
- Перемещение секции мышью и изменение высоты; положение и размер сохраняются после перезагрузки. Сброс возвращает исходную раскладку.
- Одновременные доступы мастера и персонажа, выбор роли, приглашение и QR.
- Все пять вкладок игрока, сообщения мастера и история собственного персонажа.
- Сохранение черновика и фокуса чата, а также открытого подтверждения при опросе.
- Отрицательное и пустое здоровье через настоящий ввод с клавиатуры: серверная ошибка, окно сообщения и восстановление сохранённого значения.
- Минимальная доступная повышенная ячейка, отмена без расхода, подтверждение с одной тратой и сообщением с фактическим уровнем.
- Совместные фильтры типа, ресурса и текста в редакторе; скрытый чекбокс остаётся на месте и сохраняет выбор.
- Реальная выгрузка ZIP, загрузка через выбор файла и отмена: временный архив и PNG удалены сразу, игровые записи сохранены.
- Четыре категории очистки изначально выключены; отмена ничего не удаляет.
- Заключительные изменения проверены в браузере: карточки из имени/иконки без управляющих кнопок, выбор формы сохраняется; история показывает 18 → 19 и удаление двух предметов; предложение повышенной ячейки содержит имя действия.
- Импорт показывает Новых: 0, Совпадающих: 5, Конфликтов: 1; массовый выбор архива, возврат к существующему и отдельный вариант работают, отмена удаляет временные файлы. Старый скрипт в ранее открытой вкладке исключён проверкой в свежем контексте localhost без изменения кода.

Автоматические проверки отдельно используют настоящую файловую SQLite с независимыми соединениями для конкурирующих списаний. Тесты архива проверяют атомарность, конфликт с изменившейся базой, опасные ZIP и одновременную отмену/очистку в Windows.

## Практические пределы проверки

Docker на рабочей машине не установлен. Реальная сборка контейнера, запуск Gunicorn/nginx в Linux и проверка systemd остаются подготовленными проверками CI и первого развёртывания. Workflow не запускался. Внешняя доступность 9443 и продление сертификата проверяются при отдельном деплое.

Две проверки пропущены на Windows: Gunicorn требует POSIX `fcntl`, создание символьной ссылки требует недоступной привилегии. Проверка мобильной ширины выполнялась мышью; отдельного испытания на физическом сенсорном устройстве не было.

Локальные демонстрационные данные находятся отдельно в `.browser-artifacts/preview-data`, не включаются в Git и не используют данные сервера. Экспорт тестового набора, скачанный при проверке интерфейса, находится в системной папке загрузок.

## Принятые решения и цена изменения

Ниже сохранены все решения координатора из рабочего журнала, в порядке принятия.

1. Независимые исполнители могут работать параллельно в пределах трёх агентов, с раздельными файлами. Это соответствует согласованному плану; при ошибке границ потребуется разрешить конфликт изменений.
2. Все исполнители и рецензенты используют Sol с reasoning medium по выбору пользователя. Изменение этого выбора потребует повторного распределения работы.
3. Один Django app `game` разделён на модули доступа, форм, операций, архива и HTTP; схема общая. Если границ станет недостаточно, выделение отдельных Django apps потребует переноса регистраций и миграций.
4. Игрок видит свою переписку с мастером и системные события своего персонажа. Изменение приватности потребует пересмотра получателей и проверок доступа.
5. Shell-файлы фиксируются с LF; рабочие данные, временные импорты и credential XML исключены из Git. При изменении политики хранения потребуются отдельные правила переноса и защиты данных.
6. Создание приглашения — POST с CSRF, переход по приглашению — GET с немедленным входом. Если изменить этот поток, потребуется обновить ссылки, QR и сценарий авторизации.
7. Операции Git add/commit сериализуются координатором после обнаруженного общего индекса. Работа не потеряна; ошибочное снятие этого ограничения может смешать файлы разных задач в одном коммите.
8. Из GridStack удалена только ссылка на отсутствующий debug sourcemap, иначе production collectstatic завершается ошибкой. Исполняемый код сохранён; для отладки библиотеки потребуется отдельно получить соответствующую карту исходников.
9. Архив сохраняет диапазон уже допустимых знаковых JSON-модификаторов, не вводя отдельную границу 32 бита. При необходимости строгого диапазона потребуется согласовать миграцию существующих значений; входные JSON по-прежнему ограничены размером архива.

Интеграция в другую ветку не выполнялась. Рабочая ветка и worktree сохраняются для пользователя.
